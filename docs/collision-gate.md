# The inter-arm collision gate

Written for whoever operates or tunes the rig — what the gate promises, what it
does not, and which measurements it rests on.

## What it is

Every arm agent checks each joint command **before sending it** against where
the other two arms were last reported. If the command would bring any of this
arm's links within the margin of another arm's, the command is not sent and the
arm holds. Nothing is modified or "repaired": a gate that edits commands is a
second IK solver with none of the reasoning behind it. The arm stops, the
operator backs off, teleop continues.

The code is [`rig/rig_collision.py`](../rig/rig_collision.py); the geometry is
[`rig/capsules.yaml`](../rig/capsules.yaml), generated by
[`tools/fit_capsules.py`](../tools/fit_capsules.py). Both are mounted read-only
into all three arm containers so every agent checks the **same** model — the
one deliberate exception to "no shared Python module between containers".

This is the design from giava's `capsule_gate.py`, without the GJK fine tier:
capsules only, fitted offline, numpy at runtime (about 1 ms per check).

## The guarantee

Each link is a capsule that **contains** its collision mesh (the fitter asserts
this for every vertex). So

    capsule distance ≥ margin   ⇒   the real parts are ≥ margin apart.

`ok` is a proof of separation. A refusal is conservative — the capsules pad the
true surface by 10–30 mm on these links, so the gate stops a little earlier than
strictly necessary. That cost is paid in reach, never in safety.

Per-pair margins (metres), from `rig_collision.DEFAULT_MARGINS`:

| Pair | Margin | Why |
|---|---|---|
| structure ↔ structure | 0.030 | aluminium on aluminium; covers one tick of travel + tracking lag |
| anything ↔ gripper | 0.030 | something shoving a gripper |
| gripper ↔ gripper | 0.015 | the hands meeting on purpose |
| fingertip ↔ fingertip | 0.012 | a handover |
| anything ↔ camera | 0.030 | the fragile part — but its capsule is already a 70 mm ball around an unmeasured mount, so the padding is in the shape, not the margin |

`RIG_GATE_MARGIN` sets the first two. The others are in the module.

## What it does not do

- **Self-collision.** Adjacent links of one arm overlap permanently at these
  capsule sizes, so an intra-arm check would refuse the rest pose. Joint limits
  and the operator cover it.
- **The mast, the lift, the base.** Only arm-to-arm pairs exist. Add static
  capsules to the yaml when those matter.
- **The path between two named-pose stages.** The WXAI staged moves check each
  stage's *endpoint*; the middle arm checks every 50 Hz step of its ramp.
- **Dead peers.** An arm never heard from is skipped and the verdict says so
  (`missing`). An arm that has gone quiet is taken to be where it last was.

## Escape

If two arms are *already* inside the margin — they started there, or the other
arm moved in — refusing everything would leave them stuck. A command is then
allowed if it does not make the offending pair worse. Backing off always works;
pushing in never does.

## The mounts are measured; the camera is not

The gate is only as right as the arm base positions in
[`sim/rig_params.yaml`](../sim/rig_params.yaml). They were **tape-measured on
2026-09-29** (base plate centres 21 cm either side of the middle arm, 55 cm up;
middle arm centred, 59 cm up, lift down) — before that the file held STEP-file
estimates that put the middle arm 20 cm off centre and made the left arm read
as *inside* it at rest. The offline report now:

```
$ python3 rig/rig_collision.py
  all arms at 'rest':   left  +43 mm to the ZED   right  +79 mm to middle base_link
  all arms at 'start':  left  +30 mm to the ZED   right  +79 mm
```

Two things remain approximate, and both are handled conservatively:

- **The ZED's mount** (`MIDDLE_ZED_XYZ`, still `0 0 0`). Its capsule is a
  70 mm ball about the yaw axis that contains the body at any yaw. Measure the
  mount, replace the ball with a tight capsule in `tools/fit_capsules.py`, and
  the camera margin can go back up.
- **The arms' common fore/aft offset** from the drive axle (a few cm). It moves
  all three arms together, so inter-arm distances are unaffected.

If you change any of it:

```bash
make capsules        # regenerate rig/capsules.yaml and print the offline report
make rig-urdf        # the 3D view uses the same file, so fix both at once
make clearance       # live: bring two arms close, compare the number with a ruler
```

A live disagreement of more than a couple of centimetres means something above
is still wrong. Do not tune the margin to hide it. `RIG_GATE: "0"` in the two
compose files turns the gate off.

## Reading it at runtime

Each arm publishes `<ns>/clearance` (JSON, 20 Hz) while the gate is on:

```json
{"arm": "left_arm", "holding": false, "distance_m": 0.182, "margin_m": 0.03,
 "slack_m": 0.152, "pair": ["link_6", "middle", "upper_arm_link"],
 "peers": ["right_arm", "middle"], "missing": []}
```

and logs `COLLISION GATE holding ...` (throttled) when refusing, `clear again`
when it stops.
